# Pi 자체 팀 모드 0.6.0 구현·검증 계획

목표는 Codex 대화가 없어도 Pi의 Teams만으로 일반 요청과 중간 변경을 조율하는 것이다. 요구사항은 `docs/design/2026-11-02-pi-team-mode.md`에 있다. 현재 0.5.0의 미커밋 구현과 기록을 보존한다.

## 기준과 역할

- 기준은 HEAD `86eb4fc` 위의 검증된 0.5.0 작업트리다. 최종 210개 회귀·loader·pack·Node22·실제 같은 Pi 결과/검증 흐름을 재사용한다. 코드 해시가 같은 기준을 이유 없이 다시 실행하지 않는다.
- 기준 소스 tar·파일 해시·현재 상태·프로젝트 실행 설정은 외부 `/Users/oozoofrog/.codex/visualizations/2026/11/02/codexteams-team-mode-060`에 보존했다.
- 실제 Astra task-6은 공개 API와 런타임 구조를 읽기 전용으로 검토한다. 첫 시도는 10초 제한의 광범위 경로 탐색 명령 때문에 종료됐다. 실패를 보존하고 같은 모델·작업을 한정된 경로로 재개했다. 모델 대체나 권한 실패로 기록하지 않는다.
- 실제 GPT 6.1 Terra가 src/bin/tests/package/README 및 사용자 문서의 유일한 작성자다. 실제 GPT 6.1 Sol이 현재 변경과 근거를 독립 검토한다. 각 high. Normal의 wire mapping은 미확인이다.
- Root는 설계·계획·진행·검증·외부 근거·프로젝트 `.pi/settings.json`을 소유한다. 개발과 최종 런타임 검수에 같은 Pi/Terminal 창 7016만 사용한다. 전역·인증 설정과 사용자 자동 수락은 변경하지 않는다. 후속 사용자 지시에 따라 최종 검증 후 Root가 현재 작업 브랜치를 commit·push한다. main 병합이나 전역 설치는 이 단계에 포함하지 않는다.

## 실행 순서

1. Astra의 최소 완결 구조와 공개 API 제약을 Root가 현재 요구에 맞게 확정한다. native 부모 agent와 별도 조율 worker 중 선택 근거, 요청/작업/검토 연결, 모드·세션 수명주기와 실패 시 동작을 명시한다.
2. Terra가 실제 행동을 검증하는 RED 회귀를 작성한 뒤 전체 기능을 구현한다. 테스트만 작성한 단계나 ON/OFF UI만 있는 부분 구현에서 완료로 멈추지 않는다. 요청 접수에서 결과까지 외부 Codex 없이 이어져야 한다.
3. 실패 원문과 RED·중간·GREEN 로그를 고유 경로에 보존한다. worker 안의 테스트 subprocess에서만 상속한 CODEXTEAMS 변수를 격리한다. 현재 worker의 소유권·취소 보호를 해제하지 않는다. 광범위 홈 경로 탐색과 환경 변수 덤프를 하지 않는다.
4. writer가 멈춘 현재 산출물과 근거를 Sol이 독립 검토한다. FAIL은 같은 Terra 작업의 명시적 재개로 수정하고 현재 근거를 검토한다. 검토 횟수 제한이나 자동 수락은 없다.
5. Root는 최종 source hash, typecheck/전체 회귀, loader, pack, Node22 설치 조회를 확인한다. SDK/RPC 런타임 검증은 외부 Codex가 없는 환경에서 실행한다. 완료된 무변경 검증은 재사용하고 실제 새 우려가 있는 범위만 반복한다.
6. 모든 실행·검토가 끝난 뒤 원래 프로젝트 실행 설정을 복원하고 같은 Pi를 reload한다. 실제 Pi에서 ON→일반 요청→상태/결과와 중간 입력, OFF→일반 Pi 경로를 확인한다. 모델 사용량을 소비한 실제 호출과 로컬 fixture를 구분한다.

## 필수 검증 행렬

| 범위 | 확인할 결과 |
|---|---|
| OFF/기존 사용자 | 기존 Pi 입력·기존 Teams 명령·210개 회귀 보존 |
| ON 일반 입력 | 계획·실행·독립 검토·수정·결과가 Pi 내부에서 진행 |
| 일반 질문/상태 문의 | 불필요한 구현 작업이나 파일 쓰기 없이 답변 |
| 중간 추가/변경/우선순위/중단 | 요청 보존·접수 피드백·실제 반영, 한 명의 writer |
| OFF 전환 | 새 자동 실행·늦은 완료 turn 차단, 현재 실행 의미 표시 |
| 프로젝트/세션/프로필 | trust·owner·generation·모델/effort·도구 상태 적용/복원 |
| 재시작/복구 | 모드 영속성, 저장된 미완료를 무단 재시도하지 않음 |
| 입력 출처/첨부 | extension 재귀 방지, interactive/RPC 계약, 첨부 비손실 또는 명시적 거부 |
| 완료 이벤트/라우팅 실패 | 중복 억제, stale 결과 차단, 일반 부모로의 실패 fallback 차단 |
| 최종 사용자 수락 | 내부 검토·자동 진행과 사용자 수락 기록 분리 |
| 설치본 | Node22 packaged JS lookup 및 새 상태 검증 호환성 |
| 실제 화면 | 모드와 접수/진행/대기/오류가 120×30에서 식별 가능 |

자동 테스트·실제 공급자 호출·실제 TUI·사용자 사용성 수락을 같은 결과로 합치지 않는다. 결과는 `docs/verification.md`에 현재 근거와 미확인 범위를 나눠 기록한다.

## 외부 조율이 없는 실행 증명

설정과 ON 이후 공개 Pi RPC에 일반 `prompt`를 한 번만 보낸다. 이후 테스트 클라이언트는 결과 관찰과 종료만 한다. supervisor의 run/resume을 직접 호출하거나 완료 event·수정 지시를 테스트에서 주입하지 않는다.

루프백 공급자는 제품이 실제로 호출한 역할·요청·artifact 내용을 확인한 후 모델 응답만 반환한다. writer의 실제 native 도구가 미완료 artifact를 만들고, reviewer가 실제 read로 결함을 확인하고, 다시 writer가 고친 내용을 reviewer가 확인하게 한다. 서버가 파일·상태·receipt를 대신 쓰거나 단순한 전역 호출 횟수만으로 단계를 진행하면 독립 실행의 증거로 보지 않는다.

최종 결과에는 첫 writer attempt의 FAIL과 수정된 attempt의 PASS 연결, 사용자 수락 대기, 종료 후 소유자·process 정리를 확인한다. 부모 native 모델은 poison fixture로 설정해 잘못 fallback하면 즉시 실패하게 하고 호출 수 0을 확인한다. 로컬 모델 이름은 fixture임을 명시하며 실제 Astra/Terra/Sol 사용권이나 판단력을 검증했다고 표시하지 않는다. 이 headless RPC 검증은 추가 interactive Pi를 열지 않는다.

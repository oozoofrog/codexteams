# 팀 기본 화면 구현·검증 계획

사용자 요청: “막상 사용해보니 어떻게 사용해야하는지 너무 어렵네요. 동작이 되고 있는건지도 모르겠어요.”

기준: `86eb4fc`, 0.4.0. 계약은 `docs/design/2026-11-02-team-home.md`다. 이전 0.4.0의 회귀·프로세스 수명주기 결과를 유지하고 현재 요청에 필요한 화면과 상태만 변경한다.

1. 실제 Astra high가 계약과 공개 Pi API의 실현 가능성을 읽기 전용으로 검토한다. root가 설계 결정을 확정한다.
2. 실제 Terra high가 의미 있는 상태·동작 회귀를 먼저 작성한다. controller operation, 기본 화면, 결과/행동, 상시 상태, CLI TTY 진입, 안내와 버전 0.5.0을 완성한다. root의 설계·실행 설정을 수정하지 않는다.
3. Terra는 실패 근거를 보존하고 해당 검증을 통과시킨다. 이후 typecheck, 전체 suite, loader, pack, Node22 lookup을 확인한다. 테스트 subprocess에서만 상속한 CODEXTEAMS 변수들을 격리한다. 실제 실행 소유권 표식을 제거하지 않는다.
4. 쓰기를 중지한 현재 산출물을 실제 Sol high가 독립 검토한다. 남은 결함은 같은 Terra 작업의 명시적 resume으로 수정하고 현재 근거를 다시 검토한다. 자동 수락은 없다.
5. root는 같은 Pi에서 프로젝트 실행 설정을 원복하고 `/reload`한다. 새로운 interactive Pi를 열지 않는다. 기본 화면, 작업 선택, 결과 보기, 복귀, controller check 실행/완료 상태를 확인한다. 통과한 무변경 전체 suite를 이유 없이 반복하지 않는다.

소유권: Terra는 `src/**`, `bin/**`, `tests/**`, `package.json`, `package-lock.json`, `README.md`, `docs/team-sessions.md`의 유일한 작성자다. root는 설계·계획·진행·검증·외부 근거와 `.pi/settings.json`을 작성한다. Astra와 Sol은 읽기 전용이다. commit, push, 전역 설치, 인증 변경과 기존 결과 수락은 범위에 포함하지 않는다.

확인한 실행 환경: 작업 Pi 하나를 Terminal 창 7016에서 열었다. 현재 작성 중인 소스를 host가 import하지 않도록 프로젝트 설정에서 기존 전역 0.2.1 확장을 선택했다. 전역 설치본은 수정하지 않는다. 원본 프로젝트 설정과 SHA-256은 외부 `codexteams-usability-050/pi-settings-before.json`에 보존했다. 신뢰는 이번 Pi 세션에만 적용했다.

요청 역할: Astra 설계, GPT 6.1 Terra 구현, GPT 6.1 Sol 검토. 각 high. primary OpenAI subscription 연결을 사용한다. Normal 요청의 실제 tier mapping은 확인하지 않았다. 실제 반환 모델은 attempt의 `effectiveModels`로 따로 기록한다.

## 최종 확인

210개 전체 테스트와 독립 검토, 최종 Node22 설치 probe, 같은 Pi 120×30 결과 조회·스크롤·복귀·검증 상태 전환을 확인했다. 조회는 상태 파일을 변경하지 않았고 실제 check도 모델 시도나 수락을 만들지 않았다. 실제 화면의 배경 겹침을 마지막으로 수정하고 다시 확인했다. 최종 근거와 검증 범위는 `docs/verification.md`의 0.5.0 절에 기록했다. 변경은 로컬이며 현재 Pi에 적용했다.

# codexteams launcher implementation plan

> Execute with superpowers:subagent-driven-development; preserve the sole project ledger in docs/progress.md. User has authorized implementation, README changes and push.

**Goal:** `codexteams` opens Pi and starts a fresh project's plan and eligible tasks.
**Architecture:** thin Node CLI, one explicit extension launch command, one atomic controller launch operation.
**Stack:** Node >=22.19.0, TypeScript ESM, Pi >=1.4.0 <2, native test runner.
**Spec:** docs/design/2026-11-01-launcher.md

## Global constraints

- Pi owns TUI/auth/trust; no daemon or implicit model/provider fallback.
- Human acceptance and recovery gates remain; no automatic retry of saved goals/tasks.
- No paid model calls, credentials logging or user global configuration changes during verification.
- A startup goal is processed once; cancellation/shutdown may not dispatch later work.
- One writer per assigned canonical path; independent review before integration.

## Review focus

TTY preservation and signals; literal goal handling and option boundaries; duplicate extension copies; planning-to-run cancellation gap; managed installs without peer/dev physical copies; retained state/recovery; actual executable packaging.

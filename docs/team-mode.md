# 팀 모드

이 안내는 CodexTeams 0.8.0을 기준으로 한다.

## 시작과 이어가기

프로젝트에서 팀 모드를 켠 뒤 일반 채팅으로 지시한다. `/teams mode on`은 프로젝트마다 한 번 설정하며, 기존 메뉴의 **새 요청**도 사용할 수 있다. 이후 요청 ID나 메뉴를 몰라도 질문·새 작업·진행 확인·수정·중단·재개·재검증을 요청할 수 있다.

| 하고 싶은 일 | 일반 입력 예시 |
|---|---|
| 질문 | 이 파일이 하는 일을 설명해줘. |
| 작업 요청 | README의 실행 안내를 현재 코드와 맞춰줘. |
| 진행 중 변경 | 지금 작업에서는 설치 안내부터 수정해줘. |
| 결과 수정 | 방금 결과에서 예시 문구만 더 짧게 해줘. |
| 중단·재개 | 잠깐 멈춰줘. / 아까 멈춘 작업을 이어서 해줘. |
| 검증·검토 | 파일은 바꾸지 말고 검증과 검토만 다시 해줘. |
| 진행 확인 | 지금 어디까지 했고 무엇이 남았어? |

리더는 관련 대화와 실제 작업·결과·검증 상태를 보고 직접 답하거나 필요한 담당자와 순서를 정한다. 변경은 한 번에 한 작성자만 실행하며 필수 독립 검토를 유지한다. 대상이 여러 개라면 채팅에서 짧게 확인한다. 그 질문에 일반 입력으로 답하면 된다.

## 결과와 대화 기록

진행, 구현 결과, 검증·검토 결과, 실패 이유와 필요한 다음 행동이 같은 응답 영역에 남는다. 작업 중에도 일반 입력을 계속 사용할 수 있다. 다른 화면을 열어야만 결과를 볼 수 있는 구조를 기본 경로로 사용하지 않는다. 메뉴와 원본 로그는 상세 조회·관리·복구에 사용할 수 있다.

추가 지시는 현재 실행이 끝난 뒤 적용하거나 종료를 확인한 뒤 반영한다. 성공한 단계의 파일 근거가 유효하면 그 단계를 보존하고 실제 변경 영향에 맞는 단계에서 이어간다. 검증만 다시 요청하면 구현 작성자를 다시 실행하지 않는다. 여러 요청의 결과는 대상과 revision을 구분하며 이전 기록을 최신 결과로 바꾸지 않는다.

대화 전달은 Pi 세션 이력의 실제 기록 ID와 연결한다. 전송 API가 반환했다는 사실만으로 전달 성공을 판단하지 않는다. reload·재진입 뒤에도 이력을 조정하며 불확실한 응답을 무조건 복사하거나 작업을 다시 실행하지 않는다.

## 결과 확정

수락 의사를 명확히 전달하고 필요한 확인에 답한다. 확인은 현재 대상·revision·실제 표시한 결과·파일·검증·독립 검토에 연결한다. 확인 중 근거가 바뀌면 이전 확인으로 수락할 수 없다. “좋아요”, “알겠어요” 같은 모호한 반응은 자동 수락하지 않는다. 이미 수락한 기록은 그대로 보존하고 후속 변경을 새로 연결한다.

## 모드·복구·호환

기본값은 OFF다. `/teams mode off`는 새 조율과 후속 단계를 멈추며 이미 실행 중인 작업을 자동 중단하지 않는다. 다시 ON으로 바꾸거나 프로세스를 재시작해도 이전 작업을 자동 재실행하지 않는다. 계속할 작업은 일반 채팅으로 명시한다. 비정상 종료로 남은 프로세스와 소유권 확인이 필요하면 표시된 복구 안내를 따른다. `/teams recover`와 메뉴는 고급 복구 경로로 유지한다.

새 프로젝트의 planner/designer는 Astra high, developer/reviewer는 Sol high가 기본값이다. 기존 프로젝트의 명시적 프로필을 변경하지 않는다. 모델·effort 가용성을 확인하고 사용할 수 없으면 이유를 표시한다. 지원하지 않는 모델로 자동 대체하지 않는다.

기존 0.7 데이터와 수락 기록은 새 reader에서 읽는다. 새 대화·단계 metadata를 기록한 상태는 이전 0.7 writer로 수정하지 않는다. 작업·세션·프로필·사용량과 과거 수락 근거를 보존한다.

팀 모드 입력은 현재 텍스트를 지원한다. 이미지 첨부는 접수하지 않고 안내한다. 팀 모드 ON 또는 팀 실행 중에는 부모 Pi의 쓰기·shell·알 수 없는 도구 실행을 차단한다. 리더가 선택한 팀 실행만 검증된 소유권 경로에서 수행한다.

파일 digest는 Git index와 무시되지 않은 미추적 파일을 포함한다. ignored 파일·프로젝트 밖 경로·안전하게 읽을 수 없는 심볼릭 링크나 하위 모듈은 이 검토 근거로 계산하지 않는다. 실제 사용자 수락과 테스트 fixture의 수락 검증은 구분한다.

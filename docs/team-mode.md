# 팀 모드

팀 모드는 프로젝트마다 저장하며 기본값은 OFF입니다. Pi에서 `/teams mode on`으로 켜고 일반 텍스트로 요청합니다. 팀 기본 화면에서도 모드를 전환할 수 있습니다. `/teams mode status`는 최근 요청, 상태, 조율 모델과 알려진 사용량을 표시합니다. 팀은 질문에 답하거나 요청별 구현 작업과 독립 검토 작업을 만듭니다. 기존 수동 대기 작업은 자동 실행하지 않습니다.

요청 접수는 작업 완료가 아닙니다. 팀은 선언된 검증과 독립 검토 후 사용자 확인을 기다립니다. 모델 응답이나 검토 결과만으로 사용자 수락을 기록하지 않습니다. 같은 요청 문장도 별도 입력이면 별도로 접수합니다.

진행 중 추가·방향 변경·우선순위·중단 요청은 일반 텍스트로 전달할 수 있습니다. 팀은 대상을 확인하지 못하면 요청을 대기시킵니다. worker에 입력을 실시간 주입하지 않습니다. 현재 실행 후 변경을 반영하거나 종료를 확인한 다음 같은 작업 세션을 다시 실행합니다. `/teams mode status`에서 변경 대기와 반영 상태를 확인하세요.

요청이 사용자 확인을 기다리는 동안 다른 요청이나 직접 수정으로 파일이 바뀌면 기존 검토 근거로 수락할 수 없습니다. `/teams request resume <id>`로 해당 요청의 선언된 검증과 독립 검토를 현재 파일에 대해 다시 실행하세요. 구현 worker는 다시 실행하지 않습니다. 검토에는 원래 요청, 반영된 변경 지시, 구현 작업의 인수 조건과 검증 결과가 포함됩니다.

`/teams mode off`는 새 조율과 후속 단계를 중지합니다. 이미 실행 중인 작업이나 검증은 별도 중단 요청이 없으면 계속됩니다. `/teams request stop <id>`는 해당 요청의 실행을 중단합니다. 다시 켜도 이전 대기 요청은 자동 재개되지 않습니다. `/teams request resume <id>`로 명시적으로 재개합니다. 비정상 종료 후에는 남은 프로세스와 파일을 확인하고 `/teams recover`를 먼저 사용하세요.

팀 모드 입력은 텍스트만 지원합니다. 이미지가 첨부된 입력은 접수하지 않습니다. OFF에서는 Pi의 일반 입력과 첨부 동작을 유지합니다. 팀 모드 ON이거나 팀 작업·검증이 실행 중이면 부모 Pi의 쓰기·shell 및 알 수 없는 도구 실행을 차단합니다.

독립 검토의 파일 digest는 Git index에 있는 파일과 무시되지 않은 미추적 파일의 내용을 포함합니다. Git ignored 파일과 프로젝트 밖 경로는 이 범위에 포함되지 않습니다. Git 저장소가 아니거나 파일 범위를 안전하게 확인할 수 없으면 검토는 대기합니다. Git 하위 모듈이나 심볼릭 링크도 이 검토 범위에서는 안전하게 읽을 수 없어 대기합니다.

조회 세션은 읽기 전용이며 탐색 자체가 모델을 호출하거나 결과를 수락하지 않습니다. worker와 검증의 세션 전환 동작은 [팀 세션 안내](team-sessions.md)에 있습니다. 새 팀 모드 metadata가 저장된 프로젝트는 이전 codexteams 버전으로 변경하지 마세요. 이전 버전은 이 metadata의 실행 불변식을 유지하지 않습니다.
